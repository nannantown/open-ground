# OpenGround 一般公開計画

2026-10-15。計画案。**macOSで少人数テスト後、Free／Proを一般公開**する方針はユーザー確認済み。
**AI用APIキー方式は採用せず、各利用者が自分のAIサブスクを接続する製品として商品化する。**
これはユーザーの明示方針。API方式への変更を代替案として再提案しない。
公開日・テスター人数・以下の完了条件は、この計画をもとに調整する。

細かな機能と設定の初回棚卸しは [PRODUCT_FEATURE_AUDIT.md](./PRODUCT_FEATURE_AUDIT.md)。
設定の連続保存、ブログの同時送信・送信先変更で不具合を再現した。これらは未修正。
まず設定の保存と失敗表示を直し、Ownerデータ保護、製品の表示整理、公開候補の受け入れへ進む。

## 最初に届ける製品

**複数プロジェクトとターミナルを、一つの作業場で見渡せるデスクトップアプリ。**

ユーザー方針により、製品価値と課金の中心を、自動運転からプロジェクト・ターミナルの
作業環境へ変更する。既存の `CONCEPT.md` と `docs/GTM_STRATEGY.md` の、
多数のリポジトリとターミナルを把握・切替しやすくする方向を生かす。

- プロジェクトを一覧し、目的の作業へすぐ移動できる。
- プロジェクトごとに複数のターミナルを開き、並べて操作できる。
- Boardのタスクと実行状況を、作業場所と一緒に把握できる。
- 本人のAIサブスクで使う。自動配車・監視・レビューは補助機能として位置づける。

自動運転を利用しなくてもProの作業環境に価値を感じるかを、少人数テストで確かめる。
「複数ターミナルが開く」だけでなく、プロジェクトをまたぐ切替・状況把握の負担を減らす。

| プラン | 提供方針（Free／Proの具体的な差分は再設計） |
| --- | --- |
| Free・月額0円 | プロジェクト一覧、Boardの手動タスク管理、通常のTerminal、停止・使用量・バックアップ |
| Pro・月額2,980円 | 複数プロジェクト・並行ターミナル作業の管理を強化した作業環境。自動配車・監視・復旧・独立レビュー・差し戻しも補助機能として提供する方針 |
| Owner | Songs、Canvas、Research、カスタムタブ、ブログ、実験機能等の既存権限とデータを保持 |

**現在の実装では、Freeでも複数プロジェクト・複数ターミナルを利用できる。**
従来の課金境界はSwarmであり、上記の新しい課金方針は未実装。プロジェクト数・ターミナル数の
上限や、整理・操作機能のどれでFree／Proを分けるかは未決定とする。
この計画変更だけで既存機能を制限したり、保存済みプロジェクト・セッションを削除したりしない。

- 一般画面はBoard／Terminalを中心にする。既存のデザイン方針を維持する。
- 各利用者が本人のClaude／ChatGPT契約を接続する。AI用APIキーの入力や従量課金を前提にしない。
  OpenGround Proの月額料金はプロジェクト・ターミナルの作業環境の対価とし、AI利用枠とは区別する。
  未実装・未検証の接続先や、提供元から得ていない承認を販売資料で確約しない。
- 課金名目や宣伝上の強調を変えただけで、同じ自動運転・認証実装に対する提供元の条件が
  変わったとは扱わない。自動運転を提供する場合は、補助機能でも適用条件の未解決事項を残す。
- 最初の一般公開対象はmacOS。対応CPU・最低OSは配布アプリの実機検証後に確定する。
- Windows、Codex、Owner機能の一般開放、新しい高度機能は初回公開の必須条件にしない。
- Board／Swarmの既存構造を利用する。MCP主導への再設計は行わない。

## 公開までの順番と完了条件

| 段階 | 行うこと | 次へ進む条件 |
| --- | --- | --- |
| 1. 製品仕様と前提の確定 | 作業環境としての価値、Free／Proの具体的な差分、AI認証・料金、Mac対応範囲、個人運営の問い合わせ・販売方針を整理 | 対応していない機能や認証を約束しない説明、料金・解約条件、初回導入の手順が揃う |
| 2. 出荷候補を完成 | 配布依存の更新、初回導入・エラー／未設定状態、認証・決済の実環境接続、実AIでの自動運転、署名・公証・更新を検証 | 下記の必須受け入れを通した同一の配布候補と検証記録がある |
| 3. 少人数テスト | 提案：3〜5名、まず約1週間。本人の了承を得たテスト用リポジトリで実作業し、つまずきを回収 | 導入から成果確認・停止・解約まで進められ、未解決のデータ損失・権限越境・誤課金・停止不能がない |
| 4. Free／Pro一般公開 | ブロッカー修正、販売資料、サポート・障害対応、リリース候補の最終確認 | 運営者が公開内容と証拠を確認し、明示的な公開指示後に配布・購入を開放する |

公開日は段階2の実測後に決める。外部認証の回答待ちを、実装・配布・決済検証全体の待ちにしない。
サブスク方式での商品化を進める。提供元の利用条件・承認の未確認は、公開判断時に明示する
独立した未解決事項として残す。動作確認の成功を商用利用の許可の証拠と混同しない。

### 段階2の必須受け入れ

- 新規Mac環境でダウンロード、署名・公証済みアプリの起動、CLIの検出、プロジェクト登録、
  Boardでタスク作成、通常Terminal実行・停止、再起動後の保存を一巡する。
- 本人の実ログインでFreeを確認し、Stripeテスト環境で購入→Pro反映→解約→期間終了→Free、
  支払失敗・回復、同時購入、別アカウント・端末、通信障害、Webhook再試行を確認する。
  DBのRLS／RPCも実環境で検証する。模擬応答のテストはこの証拠を代替しない。
- 本人のAIサブスク接続で、通常のProユーザーとして実Worker配車→実装→独立レビュー→
  差し戻し→再実装→完了を確認する。停止、利用枠上限、クラッシュ、再起動、契約失効も試す。
  AI用APIキーなしで検証し、接続失敗や上限到達をAPI従量課金への自動切替で処理しない。
  Ownerロールで動くことを、Proの受け入れ完了とは扱わない。
- Ownerデータの複製でOwner→Free→Owner、更新・復旧を検証する。
  Songs／Canvas／Research／カスタムタブ／ブログ設定とデータが残り、Owner以外のAPIアクセスを拒否する。
- 依存更新後にlint・型検査・全テスト・build・Free／Owner E2Eを順に実行する。
  配布ランタイムとビルド経路の重大な依存問題は解消、または実際の影響と対処を記録する。
- 署名付きの同じ配布候補でFinder起動、外部ブラウザ認証・決済からの復帰、PTY／SDK、
  安全な自動更新と復旧を確認する。実ユーザーのデータや稼働中アプリは無断で置換しない。

### 少人数テストで見ること

- 誰がどこで止まり、説明や開発者の手助けが必要だったか。初回タスク完了までの時間も記録する。
- Freeの手動操作だけで役立つか。複数プロジェクトと並行ターミナルの作業を管理しやすいか。
  自動運転を使わなくても、Proの差分に月額料金を払う価値があるか。
- 補助機能の配車・レビューを使う人は、作業を任せて状況を確認・停止できるか。
- 変更内容、停止方法、AI側の利用枠・料金、解約方法を利用者が理解できるか。
- クラッシュ、作業消失、意図しない権限・ファイル操作、契約状態との不一致がないか。
- 最初はStripeテスト環境と使い捨てデータで検証する。制御した実課金テストは、
  認証・決済・販売条件が揃った後、本人または了承した参加者で実施する。

## AI認証の前提確認

- **Codex**：問い合わせ回答を保存し、OpenGroundの具体的な構成に適用される条件を確認する。
  連絡済みと承認済みを区別する。既存構造に実行部分を追加する案を維持する。
- **Claude**：通常の未改変CLIを利用者本人が操作する場合と、第三者製品のAgent SDKで
  サブスク枠を使う場合には異なる記述がある。現在のProはSDK経路であり、適用条件は未解決。
  実装と公式条件の照合結果を記録する。承認を前提に公開日を約束せず、API方式にも変更しない。

公式資料：
[Claude Agent SDK](https://code.claude.com/docs/en/agent-sdk/overview#get-started)、
[CLIと製品組み込みの条件](https://code.claude.com/docs/en/legal-and-compliance)、
[ChatGPT利用枠連携](https://developers.openai.com/cookbook/articles/sign-in-with-chatgpt#usage-policy-and-terms)。
この計画では利用許可が得られたと扱わず、認証方式も変更していない。

## 担当と未決定事項

- エージェント：コード修正、回帰防止、隔離データによる検証、配布候補と証拠、設定手順、資料案。
- 運営者：必要な事業者情報・アカウント情報の提供、価格／税・返金・解約・サポート方針、
  外部サービス上の契約・購入など本人操作が必要な手続き、テスター選定、最終の公開判断。
- 未決定：Free／Proを分ける具体的な作業管理機能・数の上限、最初の利用者像の詳細、
  テスター人数・募集方法、サブスク接続の実装詳細、サポート窓口、
  macOSの対応範囲、公開日。価格と初回プラットフォームの決定は繰り返さない。
- 運営者情報・規約／販売表示・プライバシー資料は個人運営の事実に合わせる。架空の会社を設定しない。
- 本番データ・DBを変更しない。設定時はバックアップ、検証環境、復旧方法を用意する。
- 現在のrelease workflowはタグや既定の手動実行で公開に進み得る。
  候補作成では公開しない経路を確認し、検品前にタグをpushしない。
- 既存配布アプリの更新元・公開リポジトリの履歴を確認し、無関係な私有履歴を公開PRに混ぜない。

次の実装単位は、棚卸しのA01（設定の変更消失）とA05（保存・診断の失敗表示）。
Ownerのブログ・秘密情報・復旧の課題を保護したうえで、作業環境としてのFree／Proの差分と
初回導入の一巡を詰める。新機能の追加より先に、少人数が自分の環境で使って成果を確認できる
出荷候補を作る。
