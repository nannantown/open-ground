# 0.11.123

## 更新のあと、古い版に戻されて開き直すことがなくなります

**実現されること**

- 普通にアプリを閉じたとき、**古い版への入れ替えに「開き直せ」の指示が付くことがなくなります**。
- 普段の更新の動きは変わりません。新しい版が当たったときは、これまでどおり自分で開き直します。

**内容**

0.11.122 では、終了の直前に「入れ替えたあと開き直せ」という指示を、自分の更新に対してだけ書き込むようにしました。すでに入れ終わった残骸（稼働中と**同じ**版）には書かないようにしていましたが、稼働中より**古い**版の更新依頼が残っていた場合は、その判定をすり抜けて指示を書いてしまう並びが1つ残っていました（0.11.122 のレビューで見つかった残件）。

この版では、判定を「同じ版でなければ書く」から「**稼働中より新しい版のときだけ書く**」に変えました。版番号は数として比べます（0.11.10 は 0.11.9 より新しい）。読めない版番号のときは、これまでどおり何も書きません。この更新の仕組みでは古い版を正規に入れることはないので、この変更で失われる動きはありません。

やらないこと: 古い更新依頼そのものを消したり止めたりはしていません（開き直しの指示を付けないだけです）。Windows の更新経路は変えていません。

---

## An update never reopens the app into an older version

- On an ordinary quit, a leftover install request for an **older** build no
  longer gets a "reopen afterwards" instruction.
- Normal updates are unchanged: a newer build still relaunches the app.

**Why.** 0.11.122 writes the relaunch instruction at quit, for the app's own
install only, and skips leftovers of the **same** version. A leftover request
for an **older** version slipped past that equality check (a residual from the
0.11.122 review). The gate is now a strict comparison — only a staged version
**newer** than the running one is blessed, compared numerically (0.11.10 >
0.11.9). An unreadable or non-`x.y.z` version still fails closed. Nothing
legitimate is lost: this updater never stages an older version
(`allowDowngrade` is off).

Not in this release: the stale request itself is not removed (it just no longer
gets a relaunch), and there is no Windows change.
