# 0.11.134

## 作業の知らせが社長に届くように/更新のあとも担当が続きから再開するように

**実現されること**

- **作業が本体に入った・司令官が返事した・質問がある、といった知らせが、社長の画面に届くようになります。** これまで、社長の入力欄に薄く表示される「次に打ちそうな文」の候補を、あなたが入力中だと勘違いして、知らせを何時間も止めてしまうことがありました。あなたが本当に入力している途中の文は、これまでどおり上書きしません。
- **アプリが自動更新で再起動しても、作業中だった担当は話の続きから再開します。** これまでは再起動が速すぎると「まだ前の担当が動いているかもしれない」と判断して、作業場所だけ引き継いで最初から考え直していました。今は、その担当が本当に動いているかを確かめてから再開します。
- 再起動を待っているあいだに自動運転を止めた場合は、担当を起こしません。

## Notices reach the president again; workers resume after an update

- **Notices that work landed, that the commander replied, or that a question is
  waiting now reach the president's screen.** The dim "next prompt" suggestion
  claude shows in an empty input box was being read as you typing, which held
  notices back for hours. Text you are really typing is still never overwritten.
- **After an auto-update restart, workers that were mid-task carry on from where
  their conversation left off.** A fast restart used to look like the old worker
  might still be running, so the work restarted from scratch in the same
  worktree. The app now checks whether that worker process is actually alive.
- If you switch autopilot off while the restart is settling, no worker is
  started.
