# 0.11.130

## 社長の入力欄に知らせが打ち込まれたまま止まらなくなります

**実現されること**

- 司令官からの返事や社長への知らせが、**入力欄に打ち込まれたまま送信されない** ことがなくなります(オーナーが実画面で2回見た症状)。
- 知らせは「貼り付け → 少し待って Enter を別に送る → 本当に送れたか画面で確かめる」の順で届きます。送れたのを確かめてから次の知らせに進みます。
- **あなたが社長の入力欄に打ちかけている文字を、知らせと一緒に送ってしまうことはありません。** 入力欄に知らせの行だけが入っていて、社長が考え中でもメニュー表示中でもないときだけ Enter を押します。
- どうしても送れなかった知らせは、黙って消さずに **ベルでお知らせします**。

**内容**

これまで知らせは本文と Enter を1回でまとめて書き込んでいました。長い文だと Claude Code がそれを「貼り付け」と見なし、Enter が改行になって送信されませんでした。さらに、書き込めた時点で「届いた」と扱っていたので、入力欄に残ったまま消えていました。今回、担当への答えを届けるときに使っている確かな手順(貼り付けと Enter を分けて、着いたか確かめる)を、社長への知らせにも使うようにしました。

やらないこと: 忙しい時間帯に早めに諦めてしまうことがある点と、とても長い知らせの実測は、次の版で仕上げます。

## Notices no longer sit unsent in the president's input box

- Commander replies and notices for the president no longer **get typed into
  the input box and never sent** (the symptom the owner saw twice on screen).
- A notice is now pasted, then submitted by a separate Enter a moment later, and
  the app checks on screen that it really went through before moving on.
- **Nothing you are typing in the president's box is ever sent along with it.**
  Enter is pressed only when the box holds exactly our line and the president is
  neither thinking nor showing a menu.
- A notice that cannot be delivered is **announced on the bell** instead of
  disappearing.

**Why.** Notices used to be written as one chunk with the Enter at the end. For a
long line Claude Code treats that as a paste, so the Enter became a newline — and
the line was counted as delivered the moment it was written. The president desk
now uses the same careful routine that already delivers answers to workers.

Not in this release: giving up too early at busy moments, and a measurement of
the very longest notices, come in the next release.
