# 0.11.122

## 更新のあと、アプリが自分で開き直します

**実現されること**

- 更新が当たったあと、**アプリが自分で立ち上がり直します**。「更新したはずなのに画面が消えたまま」がなくなります。
- 普通にアプリを閉じたときに更新が当たった場合も、**同じように開き直します**（オーナーの指示による方針変更）。
- 前の版で入れた「入れ替えに失敗したら自分で直す」と合わせて、更新まわりで人が手を動かす場面をなくしていきます。

**内容**

macOS の入れ替え係は、「入れ替えたあとアプリを開き直すか」を**指示書で受け取ります**。これまでは「更新のつもりで終了したとき」にしか指示が書かれず、しかもその指示が抜ける経路があったため、入れ替えは成功しているのにアプリが戻ってこないことがありました。この版では、**終了する直前に、自分の更新に対してだけその指示を書き込みます**。

書き込みは安全側に倒してあります。指示書が読めない・壊れている・自分のものだと確認できない・**すでに入れ終わった残骸**、のいずれでも**何も書きません**。終了処理を止めないよう、失敗しても黙って諦めます（実測で1回あたり十数ミリ秒）。

あわせて、**アプリが動いている最中に入れ替えが走った事例の調査報告**を同梱しました（`docs/SHIPIT_LIVE_SWAP_0922.md`）。入れ替え係の「終了を待つ」判定は一瞬に1回しか行われず、外れると稼働中でも入れ替えます。原因の特定はまだ途中で、検知してお知らせする手当てを次に検討します。

やらないこと: Windows の更新経路は変えていません。稼働中の入れ替えを**防ぐ**手当てはこの版には入っていません（まず検知から）。

## The app reopens itself after an update

- After an update is applied, **the app relaunches itself** — no more "the update
  landed and the window never came back".
- That now includes updates that land on an **ordinary quit** (owner decision,
  2026-09-22).
- Together with 0.11.121's self-repair, the update path needs no hand-holding.

**Why.** macOS's installer takes "reopen the app afterwards" from the install
request. Until now that instruction was only written when the app quit *for* an
update — and it could go missing on the way — so an install could succeed while
the app stayed closed. The app now writes the instruction itself at `will-quit`,
for its own install only.

Every unknown fails closed: an unreadable, truncated, foreign or
**already-installed-leftover** request is left untouched, and a failed write
never blocks the quit (measured: ~13 ms per quit).

This release also ships the investigation of an install that ran **while the app
was alive** (`docs/SHIPIT_LIVE_SWAP_0922.md`): Squirrel asks "is the app still
running?" exactly once, and a miss replaces the bundle under a live process. The
root cause is still open; detection is the proposed next step.

Not in this release: no Windows change, and no prevention of the live swap yet —
detection first.
