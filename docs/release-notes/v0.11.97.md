## OPEN GROUND 0.11.97

### 仕事を任せるモデルを、Opus 基準に引き上げました

これまで補給官が振り分けるモデルは3段(fable / sonnet / haiku)で、**Opus が一度も使われていませんでした**。基準を作り直しています。

- **基本は Opus** — 普通のカードは `opus`、思考の深さは中。
- **重い設計だけ fable** — 「設計」「アーキテクチャ」「調査」といった語を含むカードは `fable` + 最大の思考。
- **超簡単なものだけ sonnet** — 誤字直し・文言変更のような軽いカードだけ `sonnet` + 最小。

### カードに、どのモデルでどれだけ考えているかが出ます

「重い / 軽い」という抽象語ではなく、**`opus/high` のように実物の名前**をカード右下に出します。何で走っているのかを、Swarm タブを開かずに確認できます。

### 列を畳めるようになりました

Board の各列の見出しに `⟨` が付きます。押すと列が縦一本のレールになり、**空いた幅は残りの列に配ります**。「判断待ち」や「完了」を畳めば、作業中の列が広くなってタイトルが読めます。畳んだ状態はプロジェクトごとに記憶します。

### 新しいものが、どの列でも一番上に来ます

とくに**完了**列がひどく、14枚のうち一番古いものが先頭にいました。カードは「移動して完了に入れる」たびに**末尾に付く**ので、新しい完了ほど下に沈んでいたためです。

- **完了は記録なので、日付順だけ** — 手で並べ替えた順番は見ません(完了列の中でドラッグしても並びは変わりません。**入れる**操作は今まで通り効きます)。
- **作業中の列(未着手・作業中・判断待ち・保留)は行列のまま** — 手で並べた順番が優先です。未着手の並びは優先度の表明なので、そこは崩しません。**手で置いていないカードだけ**が新しい順になります。
- **表示だけの変更です** — どのカードを次に取るかはサーバ側が別の基準(優先度と滞留時間)で決めているので、見た目を変えても仕事の順番は変わりません。

> 「新しい」は**作成日**で見ています。タスクに完了時刻を持っていないためで、完了時刻で並べるには保存する項目を増やす必要があります(別件)。

### 0.11.96 の宿題 — クラウドに残っていた分を消しました

前の版で「すでにクラウドに載っている分は消えません」と書いた件の続きです。**運用者のクラウドから全部消しました**(プロジェクト 21件 / メンバー 23件 / 招待 2件 / 画像 22点 4.5MiB / 本文を保持していた 41インスタンス → すべて 0)。

同時に、**古い版のアプリからの再流入をデータベース側で止めています**。アプリを更新していない端末があっても、新しく書き込まれることはありません。共有機能は**畳んだのではなく、利用者に対して閉じた**状態です(コードも設備もそのまま。再開するときは、先に「自分で消せる経路」を作ってから)。

### The base tier for delegated work is now Opus

The dispatcher used three tiers (fable / sonnet / haiku) and **never reached for Opus at all**. The ladder is rebuilt around it.

- **Opus is the base** — an ordinary card runs `opus` at medium thinking.
- **fable for heavy design only** — cards naming design, architecture, or research get `fable` at maximum.
- **sonnet for the genuinely trivial** — typo fixes and copy tweaks get `sonnet` at minimum.

### Cards say which model, and how hard it is thinking

Not "heavy / light" but **the real thing — `opus/high`** — in the card's bottom corner. You can see what a card is running on without opening the Swarm tab.

### Columns fold away

Each Board column header carries a `⟨`. Folding one collapses it to a vertical rail and **hands its width to the remaining columns**, so folding 判断待ち and 完了 makes the working lanes wide enough to read. The folded set is remembered per project.

### The newest card is on top, in every lane

The 完了 lane was the worst case: the oldest of 14 sat at the top. A card lands there by being *moved* there, which **appends it** — so every new completion sank to the bottom.

- **完了 is a record, so it sorts by date alone** — hand arrangement is ignored (dragging *within* 完了 no longer reorders; dropping *into* it still works).
- **Working lanes stay queues** — your drag order still wins, because in 未着手 that arrangement *is* the priority statement. Only cards **you never placed by hand** now sort newest-first.
- **Display only** — the server picks the next card by priority and age, so changing what you see cannot change what a worker takes.

> "Newest" means newest-*created*: a task carries no completion time. Sorting by when work actually finished means storing a new field — its own decision.

### Following up on 0.11.96 — the cloud copies are gone

0.11.96 said "what is already in the cloud is not removed". It is now: **everything was erased from the operator's cloud** (21 projects / 23 memberships / 2 invites / 22 images at 4.5 MiB / 41 instances holding actual card and canvas text → all zero).

Re-entry from **older app builds is now blocked at the database**, so a machine that has not updated cannot write new rows either. Sharing is not dismantled — the code and the infrastructure stay — it is **closed to users** until a path for deleting your own data exists.
