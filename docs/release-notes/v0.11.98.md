## OPEN GROUND 0.11.98

### アップデートで司令官が消えなくなりました

swarm が動いている最中にアプリを更新すると、**司令官の卓だけが戻ってきませんでした**。エンジンも、worker の名簿も、補給官も再起動をまたいで復帰するのに、司令官は復帰する根拠がどこにも記録されていなかったためです。

実際に起きたこと（2026-08-26 実測）: 更新で再起動 → 司令官が消える → 孤児になった worker はそのまま走り続けて**完了する** → **統合する人がいないので何も着地しない**。worker が生きているので、画面上は「動いている」ように見えます。**いちばん気づきにくい停止**でした。再起動はたいてい更新なので、作業が飛んでいる最中に起きます。

- **司令官の卓を覚えるようになりました** — 補給官と同じ仕組みです。あなたが開いた卓は、次の起動で会話ごと戻ります。
- **自動運転を切っていても戻ります** — 自動運転オフのまま司令官と話しているのは普通の状態なので、そこには連動させていません。**一時停止**にも連動しません（あれは自動運転を止める操作であって、話している卓を閉じる操作ではないので）。
- **閉じたら閉じたまま** — 停止ボタンは「意図」を記録する経路を通るようになりました。これがないと、閉じた卓が毎回の起動で蘇ります。
- **戻れなかったときは黙りません** — 補給官の不在は画面を開けば見えますが、司令官の不在は見えない（worker は動き、カードは進み、ただ何も着地しない）ので、そこだけ通知を出します。

### 実行を押すと、worker が動きます（swarm オンのとき）

カードの **実行** は claude をターミナルで起動していました。worker は SDK で動くのに、同じ「このカードをやる」が2つの別々の仕組みに分かれていた状態です。

- **swarm がオンなら、実行はカードを worker に渡します** — サーバが本物の作業フォルダを切って隔離し、終わると**判断待ち**に入って司令官が統合します。これまでの実行は「task/ ブランチを切って自分でマージして」と claude に**文章でお願い**していただけで、隔離は約束にすぎませんでした。
- **swarm がオフなら今まで通りターミナル** — 統合する司令官がいない以上、自分でマージして戻す流れしか終われないためです。
- **書いてすぐ実行しても、書いた内容で走ります** — カードの保存はわずかに遅れて反映されるので、これまでは「1つ前の内容」や、作りたてなら「空っぽ」で worker が出発しうる状態でした。今は画面にある内容がそのまま渡ります。
- **カード個別の実行設定は swarm 中は畳みました** — worker はそのどれにも従いません（進み方は必ず判断待ち→司令官、モデルは補給官が内容の重さで選ぶ）。効かないつまみを残すほうが紛らわしいので外し、代わりに何が起きるかを1行で書いています。**実際に何で走ったかはカードに出ます**（`opus/high`）。

### 完了したカードは、記録として読めます

完了列のカードにも実行ボタンが出ていました。終わったものをもう一度発射する画面になっていた、ということです。

- **実行・実行設定は出ません**。代わりに、そのカードが**実際に残したもの**だけを出します — ブランチ / プルリクエスト / 見た人 / 差し戻し回数 / 作成日。
- **無いものは書きません** — 記録が何も無いカードは「内容のほかに残っている記録はありません」とだけ言います。
- もう一度やるときは、別の列にドラッグして戻してください。

> 日付は**作成日**で、完了日ではありません。タスクが完了時刻を持っていないためです（並び順のときと同じ理由）。

### An update no longer erases the commander

Updating the app mid-swarm brought everything back except the commander's desk. The engine resumed, the worker roster reconciled, the supply desk relaunched — the commander was the one thing with nothing recorded to come back for.

What actually happened (measured 2026-08-26): the update restarted the app, the commander died, the orphaned worker kept running and **finished** — and with no commander, nothing integrates. Live workers made the board look healthy. **The hardest kind of stop to notice**, and a restart is usually an update, i.e. exactly when work is in flight.

- **The desk is remembered**, the same way the supply desk already was: a desk you opened comes back at the next launch, conversation included.
- **It comes back with autonomy off too** — a commander up while autonomy is off is the owner talking to it, so the two are deliberately not tied. Pausing autonomy does not close it either; that pauses the engine, not the conversation.
- **Closed stays closed** — the stop button now goes through a route that records the intent. Without that, a desk you just closed would return on every restart.
- **A failed comeback is loud.** A missing supply window is visible; a missing commander is not — workers run, cards move, nothing lands.

### Run now starts a worker (with the swarm on)

A card's **Run** opened a claude terminal, while workers run on the SDK — the same "do this card" split across two mechanisms.

- **Swarm on: Run hands the card to a worker** — a real isolated worktree the server cuts, then 判断待ち for the commander to integrate. The old Run only *asked* claude, in prose, to cut a task/ branch and merge itself back; the isolation was a request, not a fact.
- **Swarm off: still the terminal** — with no commander to integrate, merging it back yourself is the only flow that finishes.
- **Writing a card and running it immediately now runs what you wrote.** Card edits reach disk on a short delay, so a worker could previously set off after the previous edit — or after nothing at all on a brand-new card.
- **The per-card run settings are folded away under swarm** — a worker answers to none of them (the flow is always 判断待ち→commander; the model comes from the supply officer's card-weight policy). A control that changes nothing is worse than no control. The card still shows the model it actually got.

### A finished card reads as a record

Done cards still offered a Run button — a launcher on something already finished.

- **No Run, no run settings.** In their place: what the card actually left behind — branch, pull request, reviewer, times sent back, created.
- **Nothing is invented.** A card with no record says exactly that in one line.
- To pick it up again, drag it back to another column.

> The date is when it was *created*, not finished: a task carries no completion time (the same gap the ordering change ran into).
