# 0.11.121

## 「更新したのに古いまま」をアプリが自分で直します／知らせが窓口に届きます

**実現されること**

- 更新の入れ替えが失敗しても、**次にアプリを終了したときに自分でやり直します**。再起動1回で新しい版になります。
- 入れ替えに失敗した起動では、**理由とログを出す窓**が出ます。これまでは何も言わずに古い版で立ち上がっていました。
- エンジンや司令官からの知らせ（質問が来た・統合を保留した・カードが main に入った など）が、**話しかける相手＝タスク窓口（補給官）の席に届きます**。司令官の窓をのぞきに行かなくて済みます。

**内容**

macOS の更新は、ダウンロードのあと「入れ替え係」が別プロセスとして起動して初めて完了します。この入れ替え係が**登録されたのに一度も起動しない**ことが断続的に起きていました（0.11.112〜0.11.118 で5回）。結果、ダウンロードは成功しているのにアプリは古いまま立ち上がり、しかも何も告げませんでした。この版では、アプリが終了する直前に入れ替え係を名指しで起こします。起動時には前回の入れ替えが効いたかを確かめ、効いていなければ次の終了で1回だけ自動で復旧します。判断材料が読めない・壊れている・食い違うときは、**すべて「何もしない」に倒します**。

知らせの方は、これまで司令官の窓にしか出ていませんでした。普段あなたが話しかけるのは窓口の方なので、**知らせも窓口に届く**ようにしました。届け先は生きている窓口の席だけで、打ちかけの入力があるときは書き込まず、届いたら消えます（古い知らせは30分で期限切れ）。

やらないこと: Windows 側の更新経路は変えていません（今回の不具合は macOS 固有です）。司令官が自由に喋った言葉を窓口へ転送する経路は、この版には入っていません。

## The app repairs a failed update by itself — and the engine's news reaches the supply desk

- When the hand-off to macOS's installer silently fails, OPEN GROUND **kicks it
  by hand on the next quit** — one restart and you are on the new version.
- A boot that came back on the old version now **says so**, with the reason and
  a button that opens the updater log.
- Engine/commander news — an escalation opened, an integration held back, a card
  landed on main — is now delivered to the **supply desk**, the seat you
  actually talk to, instead of only the commander's window.

**Why.** On macOS the update only lands once Squirrel's ShipIt process runs.
Five times across 0.11.112–0.11.118 the job was submitted and never started
(`runs=0, last exit=(never exited)`, no ShipIt log line at all), so the download
succeeded and the app relaunched on the old version in silence. The nudge now
sits at `will-quit`, not at pre-flight: Squirrel writes and submits the request
at *download* time, and only `quitAndInstall` sets the relaunch-after-install
flag, so kicking earlier would install without reopening the app. Everything
unknown fails safe — an absent, truncated or contradictory install request arms
nothing, and the staged version is read from ShipIt's own request rather than
guessed from cache directories.

The notice channel writes only to a live supply desk that is idle with an empty
input box, clears on delivery, and expires after 30 minutes.

Not in this release: no change to the Windows update path, and a commander's
free-form message still has no route to the supply seat (its questions arrive as
escalations and its merges as land notices).
