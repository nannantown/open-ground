# オーケストレーション ＝ 厨房（Canvas mock アニメ図解）

OPEN GROUND の並列実行（swarm）の仕組みを、**厨房のたとえ**で図解する Canvas
の **mock 要素**ソース2点。`配る（push）` から `取りに行く（pull）` への転換を、
静止画でなく**自動再生・無限ループのアニメ**で見せる。

| ファイル | シーン | 役割 |
|---|---|---|
| `mock1-shouting-kitchen.html` | **叫ぶ厨房** — 配る (push)・**Before** | 店長が叫んで仕事を配る → 指示が料理人に届かず空中で消える → 皿が落ちる（取りこぼし）。push 方式が取りこぼす様子を絵だけで伝える。 |
| `mock2-rail-kitchen.html` | **レールの厨房** — 取りに行く (pull)・**After** | 伝票がレール（Board の todo）を流れ → 手の空いた料理人が pull → 各自の調理台（隔離 worktree）で調理 → パス台で検品 → 料理長が提供（done）。副料理長（janitor）が止まった台を自己修復。連続ループのパイプライン。 |

## 役割の対応（厨房 ↔ swarm）

| 厨房 | OPEN GROUND |
|---|---|
| 注文 | 要望 |
| 店長 | 補給官（supply・要望を伝票にして Board に積む） |
| 伝票レール | todo キュー＝Board |
| 料理長 | 司令官（commander・検品して提供＝マージ） |
| 料理人 | worker |
| 調理台 | 隔離 worktree |
| パス台 | review |
| 提供 | done |
| 副料理長 | janitor（自己修復） |

## 6原則（mock2 の凡例＋各ステーションの丸数字バッジで紐付け）

1. 取りに行く優先（pull 優先）— レール → 料理人が引く
2. 状態は外の黒板に — 伝票レール＝Board（誰の頭でもなく外から見える列）。伝票の色＝状態（todo→作業中→完了）
3. 役割分離 — 補給官／料理人／料理長／副料理長がそれぞれ一つの仕事
4. 隔離 — 各調理台が独立（混ざらない）
5. 観測可能な完了 — パス台の検品✓＋提供カウンタ（done が積み上がる）
6. 自己修復ループ — 副料理長が止まった台を直し、伝票をレールに戻す

## 使い方（Canvas に貼る）

Canvas の **mock 要素**として、`framework: 'html'` / `theme: 'dark'` で各ファイルの
中身をそのまま貼る（`src/lib/mockSrcdoc.ts` の `buildMockSrcdoc` 経由で sandboxed
iframe に描画される）。推奨サイズ:

- mock1 … **900 × 580**
- mock2 … **1240 × 680**

各ファイルは自前で暗い背景を描くので、ブラウザで直接開いても同じ見た目で確認できる
（＝ Canvas に inline したときと standalone の両対応）。アニメは pure CSS/SVG（CDN
非依存）。mock2 末尾に1つだけ JS があるが、提供カウンタを進めるだけの非必須・try/catch
ガード付きで、失敗してもシーンは動き続ける。

稼働中の OPEN GROUND を使わずに見た目だけ確認するには、ファイルをそのままブラウザで開く
だけでよい。
