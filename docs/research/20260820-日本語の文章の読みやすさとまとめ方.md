# 日本語の文章の読みやすさ・わかりやすさ・まとめ方 — 正典と数字

> シリーズ「伝わるつくりかた」三部作の②(①良いUI/UXデザインとは何か / ③リサーチ結果を伝える表現手段の選び方)。

## この調査の問い

オーナーの依頼(2026-08-20): 「文章やドキュメントを日本で読みやすさ、わかりやすさ、まとめ方に特化して調査して」。知りたいことは、**日本語の文書を読みやすくする具体的な規則と数字**。

## 30秒の答え

日本語の「読みやすさ」は気分の問題ではない。**文・段落・文書の3階層それぞれに、正典と数字がある。**

| 階層 | 核心 | 正典 |
|---|---|---|
| 文 | 一文一義。目安30〜60字。長い修飾語ほど先。読点は境界に | 本多勝一・やさしい日本語 |
| 段落 | 1段落1トピック。先頭に要約文 | 木下是雄 |
| 文書 | 結論を最初に。概要→詳細。事実と意見を分ける | ミント・逆ピラミッド・木下 |

読み手が画面の場合は、そもそも読まれない前提に立つ。紙の半分に削り、流し読みで拾える構造(見出し・箇条書き・太字)にする(ニールセン)。全階層に共通する芯はひとつ — **書き手の順序ではなく、読み手の処理順序で組む**。

## 観測: 正典と数字

### 1. 公用文作成の考え方(文化審議会建議, 2022)

昭和26年の「公用文作成の要領」を70年ぶりに全面見直しした、日本語の公的文書の現行正典。核心は公用文を**「読み手とのコミュニケーションとして捉える」**こと。SNS等の一般向け発信も対象に含め、「等」「など」「その他」を安易に使わない(示すなら全部示すか、本当に必要なものだけ書く)等の具体則を持つ。読点は「、」を原則とする(「，」からの転換)。
出典: [文化庁: 建議本文](https://www.bunka.go.jp/seisaku/bunkashingikai/kokugo/hokoku/93650001_01.html) / [発表資料](https://www.bunka.go.jp/koho_hodo_oshirase/hodohappyo/93650001.html)

### 2. 本多勝一『日本語の作文技術』(1976/新版2015) — 文の中の技術

かかり受けの明快さを技術として定式化した古典。

| 規則 | 中身 |
|---|---|
| 修飾語の語順4原則 | ①節を先に、句をあとに ②**長い修飾語ほど先に** ③大状況・重要内容ほど先に ④なじみの強い語は近くに(①②が最重要) |
| テン(読点)の二大原則 | 第一: 長い修飾語が2つ以上あるとき、その境界に打つ(重文の境界も同じ) 第二: 語順が逆順(原則から外れる)のとき打つ |

例: 「厚手の白い横線の引かれた紙」→「**横線の引かれた**厚手の白い紙」(長い修飾語を先へ出すだけで誤読が消える)。
出典: [名古屋大・鈴木氏によるまとめ](https://www.math.nagoya-u.ac.jp/~shinichiroh/2018/02/13/japanese-punctuation.html) / [朝日文庫 新版書誌](https://www.kinokuniya.co.jp/f/dsg-01-9784022618450)

### 3. 木下是雄『理科系の作文技術』(1981) — 段落と文書の技術

- **パラグラフ=1トピック**。トピックに関係ない文・反する文を同じ段落に入れない。
- **トピックセンテンス**: 段落の要約文を**先頭**に置く。読み手は1行目で主張を掴んでから詳細を読む。
- **概要→詳細(重点先行)**: 文書全体も「幹→枝」の順。
- **事実と意見の区別**: 事実(検証できる)と意見(判断)を書き分け、混ぜない。
- 報告書は「短い、歯切れのいいパラグラフ」の積み重ねにする。

出典: [中公新書 書誌](https://www.chuko.co.jp/shinsho/1981/09/100624.html) / [要点まとめ(Qiita)](https://qiita.com/e99h2121/items/dd57fd2374d7e9e0726a)

### 4. ミント『考える技術・書く技術』(ピラミッド原則) — 文書構成の技術

マッキンゼーの文書標準。**頂点に結論**を置き、下に根拠をぶら下げる。導入は **SCQA**(状況→複雑化→疑問→答え)で読み手を疑問まで連れて行ってから答える。根拠の分割は **MECE**(モレなくダブりなく)。「わかりにくい文章は文才ではなく論理構造の問題」というのが原著の主張。
出典: [ダイヤモンド社 新版](https://www.amazon.co.jp/dp/4478490279) / [安達裕哉による解説](https://note.com/yuyadachi/n/nf7cc4c832d2c)

### 5. やさしい日本語ガイドライン(出入国在留管理庁+文化庁, 2020) — 読者を広げる技術

外国人住民向けに整備されたが、中身は**万人向けの明快化技術**そのもの:

- 一文を短く(ガイドライン類の目安は**30字以内〜50・60字**)
- **一文の論点はひとつ**(一文一義)
- **二重否定・受身形を避ける**、回りくどい言い方・不要な繰り返しを避ける
- 箇条書きで整理する/イラスト・図・記号で視覚的に補う

出典: [出入国在留管理庁: ガイドライン](https://www.moj.go.jp/isa/support/portal/plainjapanese_guideline.html) / [本文PDF(文化庁)](https://www.bunka.go.jp/seisaku/kokugo_nihongo/kyoiku/pdf/92484001_01.pdf) / [第一生命経済研レポート(ガイドライン類の比較)](https://www.dlri.co.jp/report/ld/316419.html)

### 6. 一文の長さ — 数字の出どころ

| 数字 | 出どころ |
|---|---|
| **40〜60字** | 1960年代、心理学者・波多野完治が米国の文章心理学を日本語に応用して導いた古典的目安 |
| 40〜50字 | 外山滋比古「いまの日本語では40〜50字ぐらいが標準」 |
| 30〜35字 | 辰濃和男(朝日・天声人語)の実務目安 |
| 30〜40字 | 現代の各種文章の一文平均の実測 |

根拠は認知処理量(一度に処理できる情報量)と視線移動。**「短いほど良い」ではなく「一文一義が守れる上限」**として使うのが正しい読み方。
出典: [片桐光知子: なぜ40〜60字か](https://note.com/michiko_katagiri/n/n3bba8c6dd4ec) / [同: 現代平均30〜40字](https://note.com/michiko_katagiri/n/n32ed8c939b65)

### 7. 画面の読まれ方 — 逆ピラミッドと流し読み(ニールセン)

- **逆ピラミッド**: 新聞発祥の構成。最上部に最重要情報(5W1H)を置き、そこだけ読めば成立する。下へ行くほど詳細・背景。
- ニールセンのWeb文章作法: **「テキスト量は紙の50%以下に」「流し読みに対応せよ(長い連続テキストを読ませない)」**。ユーザーは画面の文章を読むのが苦手で、スキャンして拾う。
- 実務形: 意味のある見出し・箇条書き・キーワードの強調・1段落1アイデア。

出典: [U-Site(ニールセン公式日本語): サイバースペースの逆ピラミッド](https://u-site.jp/alertbox/9606a) / [同: 簡潔に!(Webの文章作法)](https://u-site.jp/alertbox/9703b) / [Wikipedia: 逆ピラミッド](https://ja.wikipedia.org/wiki/%E9%80%86%E3%83%94%E3%83%A9%E3%83%9F%E3%83%83%E3%83%89)

## 解釈: 3階層に収束する原則

*(ここからは上記ソースの統合 = 解釈)*

**文(センテンス)**
1. 一文一義 — 論点はひとつ。「〜が、〜」で繋がったら切る。
2. 目安30〜60字 — 超えたら分割を検討(機械的な上限ではなく一文一義の警報)。
3. 長い修飾語ほど先に — かかり受けの誤読はほぼこれで消える。
4. 読点は「境界」に打つ — 息継ぎではなく構造の印。
5. 二重否定・不要な受身を使わない。

**段落(パラグラフ)**
6. 1段落1トピック、先頭に要約文 — 1行目だけ拾い読みしても筋が通る文書になる。

**文書(ドキュメント)**
7. 結論を最初に — ミントも逆ピラミッドも木下も、出どころが違って答えが同じ。
8. 概要→詳細の順。導入はSCQA(読み手の疑問を立ててから答える)。
9. 事実と意見を書き分ける — 「観測」と「解釈」に節を分けるのが最も安い実装。
10. 読み手の語彙で書き、箇条書き・表・図に置き換えられる散文は置き換える。
11. 画面で読まれるなら、書いた後に**半分に削る**。

## 実務チェックリスト(文書を出す前)

- [ ] 最初の3行だけ読んだ人が、結論を正しく言えるか(結論先行)
- [ ] 各段落の1行目だけ拾い読みして筋が通るか(トピックセンテンス)
- [ ] 60字を超える文に、切れる「が」「ので」「して」が残っていないか
- [ ] かかり受けが2通りに読める文はないか(長い修飾語を先へ)
- [ ] 二重否定・不要な受身・「等」の乱用はないか
- [ ] 事実と意見が地の文で混ざっていないか
- [ ] 箇条書き・表にできる列挙が散文のままになっていないか
- [ ] 読み手の知らない用語を、初出で説明せずに使っていないか
- [ ] 画面で読む文書なら: この半分の量で同じことが言えないか

## OPEN GROUND にあてはめると(解釈)

- **今回の調査レポートの型(30秒の答え→観測→解釈→チェックリスト)は逆ピラミッド+木下の「事実と意見の区別」の実装**。この型をレポート規約として固定する価値がある。
- **要点カード(0.11.92)はトピックセンテンスの自動化** — 「各段落の要約文を先頭に」を、文書全体に対して機械がやっている。
- **plainQuestion(質問は平易文で)契約は「やさしい日本語」と同じ技術** — 一文一義・二重否定禁止・具体語。ワーカー规則に「一文60字目安」を足すと機械的に守らせられる。
- **弱点候補**: ①要点カードの1点が長くなりがち(現在240字上限) — プロンプトに「一文60字目安」を足せる。②通知 detail やエスカレーション文面に一文の長さの規律がまだない。③release notes は結論先行だが、段落の1行目要約は徹底されていない。
