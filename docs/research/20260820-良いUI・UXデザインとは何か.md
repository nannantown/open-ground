# 良いUI/UXデザインとは何か — 正典7本の原則と実務チェックリスト

> シリーズ「伝わるつくりかた」三部作の①(②日本語の文章の読みやすさとまとめ方 / ③リサーチ結果を伝える表現手段の選び方)。
> 調査日: 2026-08-20。手段: Web検索経由の裏取り(この環境は外部サイトの直接取得が不可。各主張は検索結果で複数ソースを照合し、一次URLを付した)。

## この調査の問い

オーナーの依頼(2026-08-20): 「UI/UXの良いデザインとは何かを調査できる？」。背景には前日の「OG 入力フォームのデザインださいよね」がある。知りたいことは、**何を基準に自分の画面を直せばよいか**。

## 30秒の答え

**出どころの違う7つの正典が、ほぼ同じ芯に収束している。** 工業デザイン(ラムス)・認知科学(ノーマン)・ユーザビリティ工学(ニールセン/ISO)・公共サービス設計(GOV.UK)・心理学(Laws of UX)・アクセシビリティ(WCAG)である。

収束する芯は7つ:

1. いま何が起きているかが見える
2. 相手の言葉で話す
3. 間違えても壊れない
4. 覚えさせず、見て選ばせる
5. よそと同じに動く
6. 削れるものは全部削る
7. 誰にでも・正直に

「カッコよさ」はこの上に載る層であり、装飾ではない。**美しいものは使いやすいと知覚される**という実証がある(美的ユーザビリティ効果)。

## 観測: 7つの正典

### 1. ISO 9241-11 — 「使いやすさ」の公式定義

ユーザビリティ = 「特定の利用状況で、特定のユーザーが、特定の目標を、**有効さ(effectiveness)・効率(efficiency)・満足(satisfaction)**をもって達成できる度合い」。UXはこれより広く、感情やブランドとの関係まで含む。
出典: [ISO 9241-11:2018](https://www.iso.org/obp/ui/#iso:std:iso:9241:-11:ed-2:v1:en) / [MeasuringU の解説](https://measuringu.com/iso-9241/)

### 2. ニールセンの10ユーザビリティ・ヒューリスティクス(1990/1994)

ヤコブ・ニールセンとロルフ・モリックが1990年に提唱、1994年に改訂。大量のユーザビリティ問題を説明できた原則を因子分析で10個に絞ったもの。

| # | 原則 | 一言 |
|---|---|---|
| 1 | システム状態の可視性 | いま何が起きているか、適時のフィードバックで知らせる |
| 2 | システムと現実世界の一致 | 実装用語ではなくユーザーの言葉・概念で話す |
| 3 | ユーザーの主導権と自由 | 「非常口」— 取り消し・やり直しを常に |
| 4 | 一貫性と標準 | 同じものは同じ言葉・同じ場所・同じ動きで |
| 5 | エラーの予防 | 起きてから伝えるより、起きない設計 |
| 6 | 想起より認識 | 覚えさせない。選択肢・操作は見えるところに |
| 7 | 柔軟性と効率 | 初心者にも玄人(ショートカット)にも |
| 8 | 美的で最小限のデザイン | 競合する情報を削り、要点の視認性を守る |
| 9 | エラーの認識・診断・回復 | 平易な言葉で、何が起き、どう直すか |
| 10 | ヘルプと文書 | 無くても使えるのが理想、要るなら手順を具体的に |

出典: [NN/g 原典](https://www.nngroup.com/articles/ten-usability-heuristics/)(直接取得不可のため [UXtweak](https://blog.uxtweak.com/usability-heuristics/) / [Uxcel](https://uxcel.com/lessons/usability-heuristics-270) で照合)

### 3. ディーター・ラムス「良いデザインの10箇条」(工業デザイン)

「Less, but better(より少なく、しかしより良く)」。良いデザインは — **革新的 / 有用 / 美しい / 理解しやすい / 出しゃばらない / 正直 / 長持ちする / 細部まで徹底している / 環境に優しい / できる限り少ない**。特に「正直: 実際より革新的・強力・高価値に見せず、消費者を操作しようとしない」はソフトウェアのダークパターン批判の源流。
出典: [Vitsœ(ラムス公認)](https://www.vitsoe.com/us/about/good-design)(直接取得不可のため [Design Museum](https://designmuseum.org/discover-design/all-stories/what-is-good-design-a-quick-look-at-dieter-rams-ten-principles) で照合)

### 4. ノーマン『誰のためのデザイン?』の6概念(認知科学)

**アフォーダンス**(何ができるか)/ **シグニファイア**(できることの手がかり)/ **制約**(できないことが正しい操作を教える)/ **対応づけ**(操作と結果の空間的一致)/ **フィードバック**(命令が届いたと分かる応答。多すぎても少なすぎてもだめ)/ **概念モデル**(ユーザーが頭に作る「仕組みの想像図」が正しく作れる手がかりを設計が出す)。発見可能性(discoverability)= 何ができ・どうやるかが見て分かること、が総合目標。
出典: [jnd.org(改訂版書誌)](https://jnd.org/books/the-design-of-everyday-things-revised-and-expanded-edition/) / [UX Magazine の解説](https://uxmag.com/articles/understanding-don-normans-principles-of-interaction)

### 5. GOV.UK 政府デザイン原則(サービス設計)

英国政府デジタルサービスの10箇条: **①ユーザーニーズから始める ②少なく作る(Do less) ③データで設計する ④簡単にするための困難な仕事をこちらがやる ⑤反復し、また反復する ⑥これは万人のためのもの ⑦文脈を理解する ⑧Webサイトではなくデジタルサービスを作る ⑨画一ではなく一貫 ⑩開かれた場で作る**。④「Do the hard work to make it simple」は"簡単に見えるものは裏の仕事量が多い"という設計者側の倫理。
出典: [GOV.UK 原典](https://www.gov.uk/guidance/government-design-principles)(直接取得不可のため [principles.design](https://principles.design/examples/gov-uk-design-principles) / [OECD OPSI](https://oecd-opsi.org/toolkits/government-digital-service-design-principles/) で照合)

### 6. Laws of UX(Jon Yablonski による心理法則集)

| 法則 | 中身 |
|---|---|
| ヤコブの法則 | ユーザーは人生の大半を他のサイトで過ごす — 既知のパターン通りに動くことを望む |
| ヒックの法則 | 選択肢が増えるほど決定は遅くなる |
| フィッツの法則 | 標的が大きく・近いほど速く正確に押せる |
| ドハティのしきい値 | 応答400ms以内なら人も計算機も互いを待たない — 生産性が跳ねる(1982, Doherty & Thadani) |
| ピーク・エンドの法則 | 体験の評価は「山場」と「終わり方」でほぼ決まる |
| 美的ユーザビリティ効果 | 美しいデザインは「使いやすい」と知覚され、小さな瑕疵は許容されやすい |

出典: [lawsofux.com](https://lawsofux.com/)(直接取得不可のため [UX Design Institute](https://www.uxdesigninstitute.com/blog/laws-of-ux/) / [Wikipedia: Fitts's law](https://en.wikipedia.org/wiki/Fitts%27s_law) / [Wikipedia: Peak–end rule](https://en.wikipedia.org/wiki/Peak%E2%80%93end_rule) で照合)

### 7. WCAG の4原則「POUR」(アクセシビリティ)

コンテンツは **知覚可能(Perceivable)・操作可能(Operable)・理解可能(Understandable)・堅牢(Robust)** であること。WCAG 2.2 はこの4原則の下に13ガイドライン+検証可能な達成基準を置く。
出典: [W3C WAI: WCAG 2 Overview](https://www.w3.org/WAI/standards-guidelines/wcag/)(直接取得不可のため [BOIA の解説](https://www.boia.org/blog/what-are-the-four-major-categories-of-accessibility) で照合)

## 解釈: 流派を超えて収束する7つの芯

*(ここからは上記ソースの統合 = 解釈)*

1. **状態が見える** — Nielsen#1、ノーマンのフィードバック、ドハティ400ms。「押したのに無反応」が最悪。
2. **相手の言葉で話す** — Nielsen#2、GOV.UK④。実装の都合(用語・構造)を画面に漏らさない。
3. **壊れない・戻れる** — Nielsen#3/#5/#9。破壊操作だけ確認し、それ以外は取り消しで守る。
4. **覚えさせない** — Nielsen#6、ヒックの法則。必要なものは手元に見えている。
5. **よそと同じに動く** — Nielsen#4、ヤコブの法則、GOV.UK⑨。独自UIの発明には理由がいる。
6. **削る勇気** — ラムス「Less, but better」、Nielsen#8、GOV.UK②。削って成立するなら削る。
7. **誰にでも・正直に** — POUR、GOV.UK⑥、ラムス「正直」。できないことをできると見せない。

## 実務チェックリスト(画面ひとつを出す前に)

- [ ] いま何が起きているか、画面自身が言っているか(操作への反応は400ms以内か)
- [ ] ユーザーの言葉になっているか(社内用語・実装用語が漏れていないか)
- [ ] 間違えても戻れるか(確認ダイアログは破壊操作だけに絞ったか)
- [ ] 覚えていないと使えない操作はないか(選択肢は見えているか・数は絞ったか)
- [ ] 既知のパターン(OS・主要アプリ)から外れる箇所に、外れる理由があるか
- [ ] 要素を1つ消しても成立するなら消したか
- [ ] コントラスト・キーボード操作・読み上げで詰む人はいないか(POUR)
- [ ] 実際より良く見せている表示はないか(読めなかった≠0件、進行中≠完了)
- [ ] 体験の「終わり方」は良いか(完了時の一言・後味 — ピーク・エンド)

## OPEN GROUND にあてはめると(解釈)

- **計器盤思想はNielsen#1の実装そのもの** — Groundカードのランプ(RUNNING/WAITING)や Terminal ビーコンは「システム状態の可視性」。0.11.90〜91でランプを事実に合わせた作業は、この正典どおりの方向だった。
- **「質問は平易文で」ルール = Nielsen#2**。escalation の plainQuestion 契約は正典と一致。
- **「読めなかった≠0件」の正直さ契約 = ラムスの「正直」**。この製品が最初から持っている芯で、維持する価値がある。
- **今日の質問ドック = 「想起より認識」**。入力欄が常に手元にあるのは Nielsen#6 の形。要点の自動抽出は「覚えさせない・待たせない」(ドハティ)にも合う。
- **弱点候補**: ①アクセシビリティ(POUR)は未監査 — コントラスト比とキーボード操作の一巡が最も安い一手。②応答400msの実測をしていない(重い画面の初回描画)。③確認ダイアログの棚卸し(破壊操作以外に確認を出していないか)。
