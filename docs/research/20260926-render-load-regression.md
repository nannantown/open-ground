■ 一言で
OPEN GROUND の画面そのものは、前回(昨日)からほとんど重くなっていません。15:03 に Renderer が 30〜55% に見えたのは、パソコン全体が詰まっていた(11個の頭脳に対して約130個の仕事が順番待ち)ためだと考えられます。詰まりの主因は OPEN GROUND の画面ではなく、作業係8人がそれぞれ同時に回しているテストです。

■ ① 何が重いのか(数字つき・実測)
- 実物のアプリ(15:23、60秒平均、ロード 38 まで下がった時点): 画面係(Renderer)6% / GPU係 32% / 裏のサーバー 25% / 本体 0.3%。WindowServer(macOS が全アプリの画面をまとめる仕組み)51%。前回の実物は Renderer 17% / GPU 21% / サーバー 28% で、合計はほぼ同じ。
- 画面ごと(実物と同じ画面・同じデータを別ウィンドウで開いて20秒ずつ測定。数字は「頭脳1個のうち何%」):
  - グラウンド: 画面係 4〜5 / GPU 25〜29(前回 4 / 26)。作業中カードの「流れる帯」と「点滅する印」を止めると 0.2 / 0.1。
  - Board(下のバーを畳んだ状態): 16 / 37(前回 13 / 31)。キャラクターと動きを全部止めると 6 / 5。
  - Board(下のバーを開いた状態・席のアイコン列8人分): 13〜24 / 30〜38(前回 16 / 31)。席で会話が流れている間は画面係が上がる。
  - すりガラスのぼかしを消すと GPU が約 10 下がる(前回と同じ)。
  - 画面からサーバーへの定期的な問い合わせは Board で 30秒に 49回程度。画面係の計算(スクリプト)は 1% しか使っておらず、重さの原因ではない。
- パソコン全体の混雑の内訳(90秒間に新しく起動したプロセスを数えた):
  - テストの実行(node)約350本、git 約180本以上、ネット越しの git(git-remote-https)35本、gh 10本 — ほぼ全部が作業係の仕事(テスト・取り込み・確認)。
  - そのうち OPEN GROUND のサーバー自身が起動したのは git 約50〜80本(1秒に1本弱・全体の1割前後)。作業場所の状態確認用。
  - 作業係のテストは、1回ごとに最大10個の並列プロセスを立てる(テスト道具 vitest 4.1.7 の既定値 = 頭脳の数−1。この Mac は11個)。8人が同時にテストを回すと最大約80個 → ロード 130 前後と数が合う。
- trustd / ecosystemd / ecosystemanalyticsd: 各 45〜65% に跳ねる時間帯と、ほぼ 0〜15% の時間帯があった。5秒ごとの起動数との対応ははっきりしなかった(実測では決め手なし)。trustd は通信の証明書を確かめる macOS の係なので、作業係の git 取り込み・gh などのネット通信で忙しくなる、というのが推測(未検証)。ecosystemd 系が何に反応しているかは分からなかった。OPEN GROUND のサーバー自身はネット通信をする git を起動していなかった。

■ ② OG の画面が前回より重く見えた理由
- 実測: 画面を描く負担そのものは、前回からほぼ同じ(Board で +3〜6 ポイント程度)。前回以降の変更(席のアイコン列、グラウンドの印・検索、フレーム、帯)は、それぞれ小さい。アイコン列は動いている席の分だけ動き、止まっている席のキャラクターは1枚絵で止まっている。検索の光る演出は1回きり。
- 推測(未検証): 15:03 の 30〜55% は次の2つが重なったもの。
  1. パソコンが詰まっていた: この Mac の頭脳は速い5個+省エネの6個。仕事が約130個待っていると、画面係も遅い頭脳に回されたり順番待ちで細切れになったりして、同じ仕事でも使用率の数字が2〜3倍に見えやすい。
  2. そのとき開いていた画面: Board+下のバーを開いて会話が流れていると、画面係は 13〜24 まで上がる(グラウンドなら 4〜5)。
- 前回の測定は「テストが止まっている静かな時間」、今回の社長の測定は「8人が同時にテスト中」だったので、同じ条件の比較ではありません。

■ ③ 本当に効く直しの提案
- OG の画面について: なし。一番大きいのはグラウンドの作業中カードの動き(GPU 25〜29、パソコン全体の約2〜3%)で、止めても体感はほとんど変わらない。
- パソコン全体の重さについて(作業係の人数は減らさない案): 作業係がテストを回すときの並列数に上限を付ける(例: 1人あたり最大10 → 2〜3)。8人の同時テストで立ち上がるプロセスが約80個 → 約16〜24個になり、ロードは今の数分の一になる見込み(推測・未検証)。どうせ頭脳は11個しかないので、全体の仕上がる速さはほぼ変わらず、1人あたりのテストは少し長くなる。OG の画面・会話の反応はこれで一番軽くなるはず。やるかどうかはオーナー判断(別カード)。
