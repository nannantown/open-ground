# 伝わるつくりかた — 三部作の総合チェックリスト

> 三部作(①UI/UX ②日本語の文章 ③表現手段)の結論を1枚に集約した実務用の索引。根拠と出典は各レポートにある。この1枚だけ手元に置けば足りるように作ってある。

## 三部作の地図

| # | レポート | 一言でいうと |
|---|---|---|
| ① | 良いUI/UXデザインとは何か | 流派の違う正典7本が同じ7つの芯に収束している |
| ② | 日本語の文章の読みやすさとまとめ方 | 文・段落・文書の3階層それぞれに正典と数字がある |
| ③ | リサーチ結果を伝える表現手段の選び方 | 伝えたい中身の形が手段(表・グラフ・図解・スライド・文書)を決める |

## 共通の芯(3つだけ覚えるなら)

1. **結論を最初に。** 画面も文書もスライドも、最初の3秒〜3行で答えが伝わる形にする。
2. **読み手の処理順序で組む。** 書き手・作り手の都合(実装用語、作った順)を出さない。
3. **削る勇気と正直さ。** 削って成立するなら削る。できないことをできると見せない。

## 画面を出す前(①より)

- [ ] いま何が起きているか、画面自身が言っているか(反応は400ms以内か)
- [ ] ユーザーの言葉になっているか(実装用語が漏れていないか)
- [ ] 間違えても戻れるか(確認は破壊操作だけか)
- [ ] 覚えていないと使えない操作はないか(選択肢は見えているか)
- [ ] 既知のパターンから外れる箇所に、外れる理由があるか
- [ ] 要素を1つ消しても成立するなら消したか
- [ ] コントラスト・キーボード・読み上げで詰む人はいないか
- [ ] 実際より良く見せている表示はないか(読めなかった≠0件)
- [ ] 体験の「終わり方」は良いか(ピーク・エンド)

## 文書を出す前(②より)

- [ ] 最初の3行だけ読んだ人が、結論を正しく言えるか
- [ ] 各段落の1行目だけ拾い読みして筋が通るか
- [ ] 60字を超える文に、切れる「が」「ので」「して」が残っていないか
- [ ] かかり受けが2通りに読める文はないか(長い修飾語を先へ)
- [ ] 二重否定・不要な受身・「等」の乱用はないか
- [ ] 事実と意見が地の文で混ざっていないか
- [ ] 箇条書き・表にできる列挙が散文のままになっていないか
- [ ] 初出の用語を説明なしに使っていないか
- [ ] 画面で読む文書なら: この半分の量で同じことが言えないか

## 資料を作る前(③より)

- [ ] 「その場で聞かせる」のか「あとで読んで決めてもらう」のか決めたか(スライド/文書)
- [ ] 列挙・比較・構造を、表・グラフ・図解に置き換えたか
- [ ] グラフは位置か長さで量を表しているか(円グラフ・3D・装飾に逃げていないか)
- [ ] 正確な値が大事な箇所は、グラフではなく表にしたか
- [ ] 図・画像は内容を運んでいるか(飾り画像は削ったか)
- [ ] 説明文は図のすぐ隣にあるか
- [ ] スライドなら: 見出しは断言文か・3秒で読めるか・1枚1主張か
- [ ] グラフの軸・単位・出典を書いたか

## 手段の早見表(③より)

| 伝えたい中身 | 手段 |
|---|---|
| 正確な個値 | 表 |
| 量の比較・傾向・分布 | グラフ(棒・折れ線・散布) |
| 構造・流れ・重なり | 図解(ツリー/フロー/マトリクス/ベン) |
| 実物・感情 | 写真・画像 |
| その場の説得 | スライド(断言見出し+視覚証拠) |
| 非同期の深い検討 | 文書(結論先行のナラティブ) |
