# リサーチ結果を伝える表現手段の選び方 — スライド・文書・表・グラフ・図解・画像

> シリーズ「伝わるつくりかた」三部作の③(①良いUI/UXデザインとは何か / ②日本語の文章の読みやすさとまとめ方)。
> 調査日: 2026-08-20。手段: Web検索経由の裏取り(この環境は外部サイトの直接取得が不可。各主張は検索結果で複数ソースを照合し、一次URLを付した)。

## この調査の問い

オーナーの依頼(2026-08-20): 「パワポやスライドなども情報をうまく伝える手段ですよね…いかにリサーチ内容をわかりやすく表示できるか調査してほしい。図解があったほうがいいとか、画像があったほうがいいとか」。知りたいことは、**いつ・どの表現手段(表/グラフ/図解/画像/スライド/文書)を選べばよいか**。

## 30秒の答え

「図解があったほうがいい」は半分正しい。正確には、**伝えたい中身の形が手段を決める**。

| 中身 | 手段 |
|---|---|
| 正確な個値 | 表 |
| 量の比較・傾向 | グラフ |
| 構造・流れ・重なり | 図解 |
| 実物・感情 | 写真 |
| その場の説得 | スライド |
| 非同期の深い検討 | 文書(ナラティブ) |

その上に、全手段共通の物理法則が3つある:

1. 知覚精度は**位置 > 長さ > 角度 > 面積 > 色**の順(棒・折れ線・散布図が円グラフに勝つ理由)
2. **言葉+絵は言葉だけに勝る**。ただし飾りを足すほど理解は下がる(マルチメディア原理・一貫性原理)
3. スライドは**1枚1主張、見出しは断言文**。これだけで理解・記憶が実測で上がる

パワポと文書は優劣ではなく役割分担である。Amazonがパワポを禁じたのは、「その場で聞く」道具を「あとで決める」場に持ち込んだからだ。

## 観測: 8つの正典

### 1. タフテ — データインク比とチャートジャンク(グラフの掟)

『The Visual Display of Quantitative Information』(1983)。**データインク比**(グラフ中のインクのうちデータを運ぶ割合)を1に近づけよ、**チャートジャンク**(装飾・背景画像・不要な色・過剰な罫線 =「新しい情報を伝えないインク」)を消せ、同型の小さなグラフを並べる**スモール・マルチプル**で比較せよ。
出典: [Edward Tufte 公式](https://www.edwardtufte.com/book/the-visual-display-of-quantitative-information/) / [InfoVis Wiki: Data-Ink Ratio](https://infovis-wiki.net/wiki/Data-Ink_Ratio) / [Tufte原則まとめ](https://jtr13.github.io/cc19/tuftes-principles-of-data-ink.html)

### 2. クリーブランド&マギル(1984) — グラフ知覚の階層(グラフの科学)

被験者実験で、人が量を読み取る精度を課題別に序列化した古典研究。精度の高い順に:
**①共通スケール上の位置 ②非整列スケール上の位置 ③長さ ④方向 ⑤角度 ⑥傾き ⑦面積 ⑧体積 ⑨濃淡 ⑩彩度**。
含意: 量の比較は位置・長さで符号化する(棒・ドット・折れ線・散布図)。角度と面積に頼る円グラフ、色の濃淡だけのヒートマップは、正確に読ませたい場面では不利。
出典: [原論文PDF](http://euclid.psych.yorku.ca/www/psy6135/papers/ClevelandMcGill1984.pdf) / [Wikipedia: Graphical perception](https://en.wikipedia.org/wiki/Graphical_perception)

### 3. メイヤー — マルチメディア学習の原理(図解・画像の科学)

200本超の対照実験に基づく15原理(認知負荷理論ベース)。要点:

| 原理 | 中身 |
|---|---|
| マルチメディア原理 | **言葉+絵は、言葉だけより学習効果が高い**(「図解があったほうがいい」の実証的根拠) |
| 一貫性原理 | 無関係な言葉・画像・音を**削る**ほど学習は向上(飾りの画像は逆効果) |
| シグナリング原理 | 重要箇所への目印(強調・矢印)は効く |
| 空間的近接原理 | 説明文は図の該当箇所の**すぐ隣**に置く(離すと効果が落ちる) |
| 冗長性原理 | ナレーションと同じ全文をスライドにも書くのは逆効果 |

出典: [Cambridge: Multimedia Learning(Mayer)](https://www.cambridge.org/highereducation/books/multimedia-learning/FB7E79A165D24D47CEACEB4D2C426ECD) / [DLI: Mayer's 12 Principles](https://www.digitallearninginstitute.com/blog/mayers-principles-multimedia-learning) / [メタ分析(2025)](https://www.sciencedirect.com/science/article/pii/S1747938X25000673)

### 4. 断言-証拠型スライド(Alley/Garner, ペンシルベニア州立大) — スライドの科学

見出しを話題名ではなく**主張を言い切る一文**にし、本文は箇条書きでなく**視覚的証拠**(図・写真・式)にする型。2013年の実験(工学系学生110名)で、従来の「題目+箇条書き」型に比べ**理解が向上・誤解が減少・認知負荷が低下・遅延テストでの記憶も優位**。主張は見出しに置いたときの方が、箇条書きの中に置いたときより想起されやすい。
出典: [Garner & Alley 論文ページ(Penn State)](https://pure.psu.edu/en/publications/how-the-design-of-presentation-slides-affects-audience-comprehens/) / [本文PDF](https://writing.engr.psu.edu/ae_comprehension.pdf) / [ASEE 2011 報告](https://peer.asee.org/assertion-evidence-slides-appear-to-lead-to-better-comprehension-and-recall-of-more-complex-concepts.pdf)

### 5. デュアルテ — グランステスト(スライドの実務)

『slide:ology』の著者。スライドは**3秒で意味が取れる**こと(聴衆は聞きながら一瞥するだけ)。3秒で読めないスライドは文書であってスライドではない。1枚1メッセージ。
出典: [Duarte: The Glance Test](https://www.duarte.com/resources/guides-tools/the-glance-test/) / [HBR: Do Your Slides Pass the Glance Test?](https://hbr.org/2012/10/do-your-slides-pass-the-glance-test)

### 6. Amazonのナラティブ文書文化 — 文書の実務(スライドの対抗正典)

2006年頃、ベゾスが社内会議のパワポを禁止。資料は**1ページか6ページの散文**(図・グラフ・箇条書きも避ける)にし、会議は全員が黙って読む時間から始める。理由: 箇条書きや図は**行間の解釈が読み手ごとにぶれる**が、散文は書き手に深い理解を強制し、全員が同じ認識を持てる。→ スライドが劣るのではなく、**「その場で聞く」道具を「あとで深く決める」場に使うな**という使い分けの教訓。
出典: [日経クロストレンド](https://xtrend.nikkei.com/atcl/contents/18/00447/00007/) / [Forbes JAPAN](https://forbesjapan.com/articles/detail/38119)

### 7. フュー&アベラ — 表とグラフの使い分け(数字の実務)

- **フュー**(『Show Me the Numbers』): **表 = 個々の値を調べる・正確な値が要る**とき。**グラフ = データの形(パターン・関係)がメッセージ**のとき。グラフで見せる関係は7種(時系列・順位・部分と全体・偏差・分布・相関・名義比較)。
- **アベラ**のチャートチューザー: まず「見せたいのは**比較か、構成か、分布か、関係か**」を決め、そこから変数の数で型に降りる。

出典: [Few: Effectively Communicating Numbers(PDF)](https://www.perceptualedge.com/articles/Whitepapers/Communicating_Numbers.pdf) / [Few: Graph Selection Matrix(PDF)](https://www.perceptualedge.com/articles/misc/Graph_Selection_Matrix.pdf) / [Abela's Chart Chooser 解説](https://datavizblog.com/2013/04/29/andrew-abelas-chart-chooser/)

### 8. 図解の基本型(日本の実務) と 画像優位性効果

- 図解は**関係の形**で型を選ぶ: **重なり→ベン図 / 階層・親子→ツリー / 2軸の位置づけ→マトリクス(4象限) / 時系列・手順→フロー / 内訳・構成→構造図**。
- **画像優位性効果**(Picture Superiority Effect): 絵は言葉より認識・想起されやすい。Brady et al.(2008, PNAS)では**2,500枚**の物体画像を各3秒見ただけで、後の再認テストで**87〜93%**の正答率 — 視覚記憶の容量は巨大。「実物を見せられるなら見せろ」の根拠。

出典: [ferret: 伝わる図解の作り方](https://ferret-one.com/blog/schema) / [アナグラム: 図解の作り方3STEP](https://anagrams.jp/blog/how-to-make-diagram/) / [Brady et al. 2008(PNAS)](https://www.pnas.org/doi/full/10.1073/pnas.0803390105) / [NN/g: Picture-Superiority Effect](https://www.nngroup.com/articles/picture-superiority-effect/)

## 解釈: 「伝えたいこと → 手段」変換表

*(ここからは上記ソースの統合 = 解釈)*

| 伝えたい中身 | 手段 | 型の選び方 | 根拠 |
|---|---|---|---|
| 正確な個々の値・参照用の数字 | **表** | 行=項目、列=属性。桁を揃える | フュー |
| 量の比較・傾向・分布・相関 | **グラフ** | 比較=棒 / 時系列=折れ線 / 相関=散布 / 分布=ヒストグラム。位置・長さで符号化し、円グラフと装飾は避ける | アベラ+クリーブランド&マギル+タフテ |
| 構造・流れ・位置づけ・重なり | **図解** | 階層=ツリー / 手順=フロー / 2軸=マトリクス / 共通部分=ベン | 図解の基本型+メイヤー(マルチメディア原理) |
| 実物・現場・感情・記憶への定着 | **写真・画像** | 内容に関係あるものだけ(飾り画像は逆効果) | 画像優位性効果+一貫性原理 |
| その場で聞き手を動かす(発表・提案) | **スライド** | 1枚1主張・見出しは断言文・本文は視覚的証拠・3秒で読める | Alley/Garner+デュアルテ |
| 非同期で深く検討してもらう・決めてもらう | **文書(ナラティブ)** | 結論先行の散文。行間を残さない | Amazon+ミント(第2弾レポート) |
| 不特定多数に読み流してもらう(ブログ/Web) | **Web文書** | 逆ピラミッド+見出し・箇条書き・段落ごとの図解や画像で「流し読みの足場」を作る | ニールセン(第1・2弾レポート)+本稿の図解・画像則 |

読み分けの軸は3つ: **①読者はその場にいるか(同期=スライド/非同期=文書)、②中身は数字か構造か物語か、③正確さと速さのどちらを優先するか**。

## 実務チェックリスト(資料を作る前)

- [ ] これは「その場で聞かせる」のか「あとで読んで決めてもらう」のか決めたか(スライド/文書の分岐)
- [ ] 散文で書いた列挙・比較・構造のうち、表・グラフ・図解に置き換えられるものを置き換えたか
- [ ] グラフは位置か長さで量を表しているか(円グラフ・3D・装飾に逃げていないか)
- [ ] 正確な値が大事な箇所は、グラフではなく表にしたか
- [ ] 図・画像は内容を運んでいるか(雰囲気だけの飾り画像は削ったか)
- [ ] 説明文は図の該当箇所のすぐ隣にあるか(図と文が離れていないか)
- [ ] スライドなら: 各枚の見出しは「断言文」か・3秒で読めるか・1枚1主張か
- [ ] グラフの軸・単位・出典は書いたか(誠実さ=タフテの graphical integrity)

## OPEN GROUND にあてはめると(解釈)

- **要点カードは「断言-証拠型」の見出しの自動化と同型** — 要点1行=断言文。プロンプトに「各POINTは主張を言い切る一文(体言止め・話題名は不可)」を足すと型が締まる。
- **調査レポートは現状「文書+表」まで**。renderMarkdown は表対応済みだが**図解(ツリー/フロー/マトリクス)とグラフの描画手段がない** — /research スキルの報告規約に「構造は図解、比較はグラフ」と書いても、今は描く場所がない。Mermaid級の図解レンダラ対応が次の種(安全設計は既存の renderMarkdown と同じ「テキストからノード構築・innerHTML不使用」を踏襲できる)。
- **レポート→スライド変換**(発表用の断言-証拠型スライドを要点カードから生成)は、要点=断言文が揃えばほぼ機械的に作れる将来カード。
- **画像**: レポートに現場スクリーンショットを貼る慣習はまだない。調査ワーカーに「実物が撮れるなら1枚」則を足す価値がある(画像優位性効果)。
