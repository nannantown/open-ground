# swarm・リサーチ機能を全ユーザーに公開してよいか — 監査結果と条件

> 調査日: 2026-08-20。手段: コードベースの並列監査(6リーダー+敵対検証、Workflow)。全リスク主張を敵対検証で裏取り。

## この調査の問い

オーナーの依頼(2026-08-20): 「swarm機能とリサーチ機能もONにすれば全てのユーザーがつかえるようにしたい。だけどまだ調整中だから注意書きをだして、ONにしたい場合だけONにしてもらったらいい…本当に全てのユーザーに公開していいかも調査して」。知りたいことは、**この2機能を全ユーザーに開放して安全か。安全なら、どういう形(opt-in+注意書き)なら妥当か**。

## 問いへの答え

**セキュリティ上は「はい、安全」。製品成熟度上は「まだ無条件では不可 — opt-in+正直な注意書きが必須」。** つまりオーナーの判断(ONにしたい人だけON+調整中の明記)がちょうど正しい対処。

| 観点 | 判定 | 根拠(すべて敵対検証でCONFIRMED) |
|---|---|---|
| テナンシー/攻撃面 | **安全** | 全インストールが 127.0.0.1 限定の単一ユーザーローカルサーバ。swarm ゲートはコード自身が「可視性フラグ、セキュリティ境界ではない」と明記(`POST /api/terminal` は既に無認可で任意シェルを起動できる)。公開はアプリ内ゲート変更のみで、共有バックエンドは無い |
| リサーチのサーバ側 | **既に全開** | Research タブは常時ONの既定モジュール。全 `/api/research` ルートは認可ゲート無し(パス系は validateProjectPath のみ)。「公開」はサーバ的には無操作 — 必要なのは注意書きだけ |
| コスト | **要注意・要開示** | swarm/research とも**ユーザー自身の claude サブスクを消費**。swarm はピーク約8並列(6ワーカー+司令官+補給官)、上限なし(レート制限の冷却のみ) |
| 権限バイパス | **要注意・要開示** | swarm ワーカーも research の digest/ask も `--dangerously-skip-permissions` で claude を起動。ワーカーは worktree 隔離+PreToolUse ガードで守られるが、**司令官/補給官デスクはガード無しのバイパスで、ユーザーの実リモートに push できる**(`git push origin HEAD:main`)。research は**実リポジトリ直下**でバイパス実行 |
| 言語 | **要修正** | swarm の通知・エスカレーション文面は**ハードコードの日本語**(言語切替は未配線)。英語ロケールのユーザーが swarm を有効化すると日本語通知が届く |
| プラットフォーム | **要限定** | Windows でのガード有効性は未検証(POSIX前提)。OSサンドボックス層も無し |

**開放の設計上の要点(安全に開くには)**: `eligible`(owner)フラグを一律に開けると **sandbox(権限バイパスのSeatbelt実験)と persona(オーナー個人コーパス)も一緒に開いてしまう** — 開けるのは `swarm` だけにする。research は既に全開なので、サーバゲートは足さず注意書きのみ。

## 観測: 監査の事実

### 1. 現状のゲート構造(gating-today)
- Swarm は二重ゲート: タブは owner-AND-toggle の実験フラグ(サーバ側 `computeExperiments`)で非表示、かつ全 `/api/swarm` ルートが独立に `hasSwarmOwnerAccess()` で 403。タブを隠すだけがガードではない。
- ローカル解放は `OPENGROUND_LOCAL_OWNER=1` か手編集の `swarmLocalOwner`(USER_SETTINGS_KEYS に無く POST 不可)。
- Research はゲート無し・常時ON。
- 出典: `src/lib/server/experiments.ts` computeExperiments、`src/lib/server/swarmGate.ts`、`server/routes/swarm.ts`(403 スイープ)、`server/routes/research.ts` ヘッダ、`moduleRegistry.tsx`。

### 2. swarm の影響範囲(swarm-blast-radius)
- ワーカーは worktree 隔離+PreToolUse ガード(全 git push 拒否)。司令官/補給官はガード無しで実リモート push 可。
- 失敗時は通知+バックオフ再試行。既知の暴走(ワーカーが約1時間で死ぬ・双子ブランチ増殖・通知40分遅延)が、オーナーが swarm を owner-only に留めてきた理由そのもの(GAP-1)。
- claude のフォルダ信頼ダイアログは自動承諾され、ユーザーの `~/.claude/settings.json` を書き換える。
- 出典: `swarmWorkerSdk.ts:233`、`swarmSupply.ts`、`docs/SWARM_SAFETY_INVARIANTS.md §E`、`docs/commander/TARGET-STATE.md`。

### 3. リサーチの影響範囲(research-blast-radius)
- X/Twitter クッキーは `~/.openground/research-auth.json`(0600)にのみ保存。どのルートも値を返さない(真偽値のみ・書込専用、テストで固定)。**ただし設定後は research 系でないものも含め全 swarm ワーカー spawn の env に注入される**。
- レポートを開くと digest が1回だけ自動起動(haiku・バイパス・≤180s・出力上限あり)。
- プロンプトインジェクション面: レポートは信頼できない Web/SNS 由来の内容で、その内容の上でバイパス claude が実リポジトリを cwd に走る。読み取り専用ルールはプロンプト文のみ(構造的な disallowedTools 拒否リストは無い)。
- 出典: `researchAuth.ts`、`researchKnowledge.ts:241`、`swarmWorker.ts:806`、`skills/research/SKILL.md:129-130`。

### 4. 成熟度ギャップ(readiness-gaps)
- 日本語ハードコード通知(言語壁)。TARGET-STATE §5/§8/§8b/§9 が未計測。安全ゲートの穴(`SWARM_CODE_PATHS` が `useSwarmEngine.ts` と `build-server.js` を除外)。センサーが claude の TUI 表記に依存(CLIバージョン差で盲目化)。
- 出典: `docs/commander/TARGET-STATE.md`、`docs/PLATFORM-GAP-LEDGER.md`、`CLAUDE.md` 言語ポリシー節。

### 5. 設定面と配布実態(settings-surface / distribution-reality)
- opt-in トグルの置き場所は SettingsPanel の実験セクション(既存 idiom を流用)。`Settings.experiments` は既に POST 許可済み。
- 「全ユーザー」= 公開 GitHub(nannantown/open-ground)配布のデスクトップアプリの各インストール。各々ローカル単一ユーザー。共有バックエンド無し。
- サブスク専用(API キー不使用)を確認。コストはユーザー自身のプラン。

## 解釈: 推奨する開き方

*(ここから統合=解釈)*

1. **`swarm` フラグだけを owner-AND から外す。** `sandbox`/`persona` は owner-only のまま。`computeExperiments` で `swarm = owner || (明示opt-in)` に。
2. **`/api/swarm` の seam は残す。** `hasSwarmOwnerAccess` を「owner または opt-in 済み」に読み替え、`validateProjectPath` とボディ前ゲートは維持。タブだけ開けてルートが403、の片肺を避ける。
3. **research は注意書きのみ。** 既に全開なので、実際にOFFにできるトグルにするなら別途サーバゲートが要る(いまは無い)。最小案は「注意書き+ONで使える(=現状のまま)」。
4. **注意書きに正直な3点+α**: ①自分の claude サブスクを消費(swarm は最大約8並列)②権限プロンプトをバイパスして claude を worktree/リポジトリ内で走らせる ③swarm 通知は当面日本語 ④research はローカルにクッキーを平文保存しScraping系はToSグレー。
5. **番人テストは書き換えて赤で実測**(消さない): `swarmSafety.routes.test.ts`(既定=施錠)等を「トグルOFFなら全ルート403、ONなら通る」に。
6. **Windows は限定 or 明示**: ガード未検証なので、swarm 注意書きをプラットフォーム別にするか macOS 限定にする。

## オーナーが決めること(実装前に確認したい)

- **Windows**: swarm を当面 macOS 限定にするか、Windowsでも出して注意書きで断るか。
- **research のバイパス硬化**: 公開前に digest/ask に disallowedTools 拒否リスト(Bash/Write/Edit/WebFetch等)を足すか、注意書きで開示して現状のまま出すか。
- **research のトグル**: 実際にOFFにできるサーバゲートを新設するか、注意書きのみ(=常にON)にするか。
