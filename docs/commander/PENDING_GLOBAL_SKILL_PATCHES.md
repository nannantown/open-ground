## 1. `~/.claude/skills/supply/SKILL.md` — 起票テンプレに当たり欄+粒度規約を追加

**起票日**: 2026-07-18
**理由(実測)**: swarm worker の完了までの手数を比較したところ、起票時に「当たり」(触るファイルの
明記)があるカードは 101〜126 手で完了、探索から始めたカードは最大 345 手だった(3.4 倍)。探索
コストはカード作成時に1回だけ払い、結果をカードに焼き込むのが最も安い。

**適用対象**: `~/.claude/skills/supply/SKILL.md` の「## 仕事の流れ(ユーザーが要望を言うたび)」
節、手順3「**観測可能なタスクに整える**」の notes 記述部分。

### 適用手順

`~/.claude/skills/supply/SKILL.md` の以下のブロックを:

```markdown
3. **観測可能なタスクに整える**:
   - **title** = 短い名前（Board 表示＋司令官が worker に渡す1行ゴールの素）。
   - **notes** = 要件本体。worker は司令官経由で `/order ゴール: …` として受けるので、notes には
     **観測可能な完了条件**＋必要なら**チェックリスト**＋**触る範囲/制約**を書く。
     「完璧」「最高」など**無限大の表現は禁止**——計測可能な代理指標（特定の挙動・テスト緑・
     チェックリスト消化）に必ず翻訳する（[[order]] のゴール規律と同じ）。
   - 大きい要望は**独立サブタスクに割って複数カード**に（触るファイルが重ならない単位＝並列が楽）。
```

次のように差し替える(追加ブロックは太字部分。既存の他項目はそのまま):

```markdown
3. **観測可能なタスクに整える**:
   - **title** = 短い名前（Board 表示＋司令官が worker に渡す1行ゴールの素）。
   - **notes** = 要件本体。worker は司令官経由で `/order ゴール: …` として受けるので、notes には
     **観測可能な完了条件**＋必要なら**チェックリスト**＋**触る範囲/制約**を書く。
     「完璧」「最高」など**無限大の表現は禁止**——計測可能な代理指標（特定の挙動・テスト緑・
     チェックリスト消化）に必ず翻訳する（[[order]] のゴール規律と同じ）。
   - **当たり欄（必須）** — notes に積む前に対象コードを補給官自身が1回調査し、
     **触るファイル**（分かる範囲で `file` または `file:line`）・**関連テスト**・
     **参考ドキュメント**を明記する。探索コストは起票時に1回だけ払い、結果をカードへ
     焼き込む（worker に探索からやらせない）。
   - **粒度規約（必須）** — 1カードは worker が数十手（目安 **≤120 手**）で完了する大きさに
     切る。大きい要望は **disjoint（触るファイルが重ならない）** なサブカードへ分割する。
   - 根拠（実測・2026-07-18）: 当たり欄ありのカードは worker 101〜126 手で完了、探索から
     始めたカードは最大 345 手（3.4 倍）。探索コストは起票時に一度だけ払うのが最も安い。
   - 大きい要望は**独立サブタスクに割って複数カード**に（触るファイルが重ならない単位＝並列が楽）。
```

（「当たり欄」「粒度規約」の2箇条は「大きい要望は…複数カードに」の**前**に挿入 — 粒度規約が
分割の判断基準を先に与えるほうが読み順として自然なため。既存の disjoint 分割の文言と重複気味
だが、根拠の実測値を明記する箇条として独立させておく。）
