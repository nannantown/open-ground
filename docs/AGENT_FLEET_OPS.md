# 自律エージェントの艦隊を、信用せずに運用する(社内ノート)

> **状態: 社内文書(2026-08-13 オーナー判断 — 公開はしない)。**
> docs/commander/(7 章 + TARGET-STATE)と docs/VERIFICATION.md に記録された実事故から
> 蒸留した設計原則の一枚もの。詳細は各正典が持つ — これは「何が転移するか」の索引。
> 将来公開したくなったら: 末尾の公開時付記メモを読み、固有名詞・内部パス・生々しい
> 数字の残し方を目視で見直してから(このノートは一般化済みのつもりだが、最終確認は人間)。

---

私は OPEN GROUND という個人用ツールの中で、Claude Code のセッションを「艦隊」として
運用している。かんばんの todo 列にカードを置くと、エンジンが 3 秒ごとの tick で
worker(隔離 worktree + 独立した Claude セッション)を配車し、完了を検知して review 列へ
運び、統合担当の別エージェント(司令官)を起こす。人間の仕事は注文と、不可逆な決定への
回答だけ — 理想的には。

この記事は、その理想と現実の差分から出てきた原則集である。原則はどれも思想からではなく
**日付のある事故**から生まれた。おそらく「マルチエージェント」固有の話ではなく、
自律性への委任一般 — エージェントに留守を任せるすべての設計 — に転移する。

## 1. AI の遵法は安全装置ではない

**事故(2026-07-15)**: エンジンの自動統合(4 つのレンズによる敵対レビューで全票 clean なら
main へ FF push)が、人間の差し戻し作業と並行して穴あきブランチを main に統合した。
レンズ 4 票は認証コードの取りこぼしを見逃していた。

**原則**: 「してはいけない」をプロンプトで教えるのは規範であって装置ではない。
装置とは**経路の不存在**である。この事故の後、エンジンから統合経路そのものを撤去した —
エンジンは ready を検知して司令官を起こす**だけ**になり、「エンジンのレビュー結果だけで
main が動く経路はゼロ」を回帰テストでピンした。以後この型の事故は構造的に起きない。

推論: 禁止操作のテストを AI にやらせると、AI 自身が「それは危険なのでやりません」と
断ってしまい、安全装置ではなく AI の遵法をテストしてしまう。安全装置の検証は、
断る理由のない普通の操作で規則に触れるものを選ぶ。

## 2. 自己申告は宣言であって、証明ではない

**事故(2026-07-07)**: worker の「完了しました」報告を信じた司令塔が、実際には
黙殺されていた Board 書き込み(短縮 id が 200 のまま no-op)の上に誤診を 2 連発した。

**原則**: エージェントの報告は昇格の入力にしない。エンジンの promote ゲートは worker の
「readyToMerge」宣言に加えて `git rev-list --count`(trunk より先のコミットが実在するか)を
必須にする。「書けたはず」ではなく読み戻す。「done と言った」ではなく成果物を数える。

## 3. 番人(ガードのテスト)は、赤くなるのを見るまで信用しない

**実測**: 棚卸しの番人に既知の欠陥を 4 件植えたら、4 件ともすり抜けた。
`typeof f === 'function'` を見るテスト群は、機能を全部空実装にしても 76 件緑のままだった。

**原則**: テストを書いたら、**本番コードを一時的に壊して赤を実測**してから信用する
(変異テストの手作業版)。赤が出ない番人は消してよい — 安心を配るだけで検出しない。
同じ LLM がコードもテストも書く環境では、生成の盲点と検証の盲点が相関するので、
「緑」は独立した証拠にならない。独立性は構造(壊して赤)と実機でしか買えない。

## 4. 判断はモデルへ、権力は構造へ、価値観は人間へ

事故 1 の解決は「自動統合をやめて人間が全部やる」では**なかった**。統合の判断
(重量級レビュー)は別のエージェント(司令官)に移し、統合の権力(FF push)は
その司令官の手動操作 + 安全規約に縛った。機械的なレンズ投票より 1 体の判断エージェントの
ほうがレビューの質は高く、その司令官にも main を無条件で動かす自由はない。

三層をきれいに分けると: **worker = 手**(コードとコミットだけ)、
**engine = 神経系・反射**(検知・配車・回収・蘇生 — 判断しない)、
**manager = 脳**(判断する — ただし権力は構造に縛られる)。そして**価値観 — 不可逆の線 —
は人間に残る**。リリース、削除、モデル選択の政策、エージェント自身が提案した作業の承認。
この境界は「まだ自動化できていない」のではなく、**恒久に自動化しない**と文書で宣言している。

## 5. エスカレーションは自信ではなく、可逆性で切る

worker の質問に毎回人間が答えると自律性は死ぬ。かといってエージェントに全部答えさせると
不可逆な決定が漏れる。解: 「オーナーの過去の判断記録(corpus)だけを根拠に、オーナーとして
答える」代理エージェントを置き、その弁を**可逆性**で切る — どれだけ確信があっても
不可逆(課金・公開・削除・資格情報)は人間へ、corpus が薄い領域は捏造せず「分からない」を
宣言して人間へ(校正された棄権)。

防御は二層で、どちらも単独では信用しない: 意味判定(LLM — パラフレーズを捕まえる)と
構造判定(静的分類器 — プロンプト注入で汚染された LLM の出力を後段でもう一度ゲートする)。
入力だけゲートして出力を素通しする設計は、注入 1 発で終わる。

## 6. 「読めない」は「無い」と違う

**事故(2026-08-02)**: 設定ファイルが読めない(权限・破損)とき、reader がそれを
「キー不在」と同じ既定値に潰していた。結果: ①明示的に OFF にしたはずのキルスイッチが、
ファイルが読めなくなった瞬間に ON 側へ反転 ②read-modify-write の書き手が「読めなかった
現在値 = 既定値」を新しい真実として書き戻し、登録プロジェクト一覧が丸ごと消えた。

**原則**: 読みの結果は `ok / absent / unreadable` の三値で区別する。unreadable は
安全側(fail-closed)へ、absent だけが既定値へ。そして **unreadable なファイルには
書かない**(書き込み保護) — 世代バックアップでは救えない。「現在の内容を退避してから書く」
方式は、現在の内容が読めない瞬間に無力になる。

## 7. 表示は実効値から導出する — 生の設定から再導出しない

**事故(同日)**: サーバは規則どおり PTY で動いているのに、パネルはクライアント側で
生の設定値から規則を**再実装**して SDK と描いた。この乖離が「スイッチが効いていない」と
誤読させ、オーナーにトグルを押させ、上の事故 6 の引き金になった。

**原則**: UI は「サーバが実際に使った値」を受け取って描くだけにする。同じ導出規則を
2 箇所に書いたら、それはいつか別々の答えを出す。サーバが答えないとき、UI は推測せず
「分からない」を描く(disabled)— 誤った OFF 表示は空欄より悪い。

## 8. 観測は公式信号の上に建てる。無ければ、それは技術的負債として記帳する

モデルの利用上限(quota)を検知するために、うちのエンジンは五層の機構を持っている —
冷却テーブル、TUI 画面の文言スクレイプ(45 秒沈黙でサンプリング、装飾再描画で時計が
巻き戻らないよう文言出現時刻でクランプ)、モデルマスク、usage キャッシュ、起動前プローブ。
検知遅延を 21 分 30 秒から 2 分以内に詰めるまで、事故調査を何往復もした。

これは自慢ではなく**負債の告白**である。プラットフォームが per-model quota API を公開した
瞬間、この五層は資産から負債に変わる。教訓: 公式に存在しない信号の上に建てた観測は、
全部「待てば消える工事」の台帳に記帳し、**維持のみ・拡張禁止・削除トリガ**を各行に付ける。
台帳の理想の最終状態は空。

## 9. エージェントのテスト実行は、本番データの隣で起きる

**事故(2026-07-18)**: テストスイートの HOME 隔離装置がトートロジー(自分で作った値を
自分で検査 — 絶対に発火しない)で、vitest が実運用の設定ファイルを上書き。登録 45 件が
3 件になり、キャンバス配置はバックアップ無しで永久喪失した。

**原則**: 艦隊の worker は完了ゲートで日に何十回もテストを走らせる — つまり
**エージェント運用とは、本番データの隣で毎日テストが走る運用**である。隔離は
「テスト側の行儀」ではなく本番側の fail-closed フェンス(解決の瞬間に throw する
単一チョークポイント)で実装し、フェンスを外すと赤くなることを実測しておく。

## 10. ドキュメントは事故の貯金箱 — ただし現物が正

うちの運用文書は「症状 → 直行先」の表、「信じてよい表示・信じてはいけない表示」の表、
そして日付つきの追記群でできている。将来の司令塔(たいてい記憶を失った別セッション)が
同じ誤診を繰り返さないための構造で、実際に誤診 4 件からこの文書群は生まれた。

2 つの運用規則が要る: **主張と現物が食い違ったら現物が正**(文書も古びる — そのとき
文書を直す)。そして参照は行番号ではなく**シンボル+grep**で書く(行番号は基準コミットの
台帳管理という税を将来の全読者に課す。うちはその税を払いすぎてから気づいた)。

## まとめ — 何が転移するか

配管(quota スクレイプ、PTY 管理、心拍プロトコル)は 1 年で古びる。転移するのは:

1. 安全は**経路の不存在**で実装する(§1)— そして賢いモデルほど委任は増えるので、
   この層の重要性は**増す**
2. 昇格・完了・統合のゲートは**観測可能な証拠**を要求する(§2)
3. ガードは**壊して赤を見る**まで存在しない(§3)
4. **判断・権力・価値観**を別のレイヤーに置く(§4)
5. エスカレーションの弁は**可逆性**(§5)
6. `absent ≠ unreadable`、表示は実効値、観測は公式信号の上(§6-8)
7. 隔離は本番側のフェンス(§9)、文書は事故駆動で症状から引ける形(§10)

一言に潰すなら: **賢いエージェントを信用する仕組みではなく、信用しなくても回る仕組みを
作る。** 信用は後から、実測で、少しずつ返してもらえばいい。
